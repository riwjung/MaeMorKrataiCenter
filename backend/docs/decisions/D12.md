# Decision D12: Client Contract Review for SPEC-002a

- **Date**: 2026-11-25
- **Spec**: [SPEC-002a](../specs/SPEC-002a-master-data-schema-seed-public-read.md)
- **Contract**: `docs/api/client/openapi.yaml` v0.2.0 → v0.2.1
- **Status**: APPROVED (owner, 2026-11-25)

## 1. Context & Problem Statement
D11 item 5 moved the frontend review of the client contract to the owner, as the first step of planning SPEC-002a. The Spectre split audit left two notes: the contract said both "unknown paths return 404" and "a write on any path returns 405", which conflict for a write to an unknown path; and its `servers` list named `api-staging.maemorkratai.com`, which does not exist.

## 2. Decision
1. **Write methods vs unknown paths.** A POST, PUT, PATCH or DELETE on a **known** path returns `405` with an `Allow` header listing the accepted methods. An **unknown** path returns `404` whatever the method. Both use the standard error envelope and `Cache-Control: no-store`. This applies to every `client` route, including `/health` (today axum answers a POST to `/health` with a bare `405` and no envelope). `OPTIONS` preflight keeps the SPEC-001 CORS behavior.
2. **Servers.** Staging is `https://maemorkratai-backend-client-staging.maemorkratai.workers.dev`. Production stays `https://api.maemorkratai.com`, marked as planned and not deployed.
3. The contract is otherwise accepted unchanged and bumped to v0.2.1.

## 3. Review Evidence (2026-11-25)

Facts for the planners (not contract changes):
- Daily card order differs from `reading-cards.json` order, as SPEC-002 §4.3 says; each needs its own `sort_order`.
- Daily string fields hold few distinct values today (`reading_mode`: `daily_single`; `time_horizon`: `today`; `orientation`: `upright_only`; `content_status`: 2 values). They stay plain strings, as the contract types them.
- Longest stored texts: daily 640 code points, `details` 202, `meanings` 68.
- The Workers Free plan limits apply (research 2026-11-20): 10 ms CPU per request, 50 D1 queries per invocation, 5M D1 rows read per day. `GET /v1/cards` reads about 1,000 rows (78 cards plus 936 love-status texts) and returns about 255 KB.

## 4. Consequences
- `client` needs a router-level method-not-allowed fallback that produces the envelope, `no-store` and `Allow`; the existing `404` fallback stays.
- **Frontend switch (outside SPEC-002a, D11 item 3):** the 3-card result's "ที่มาของความหมาย" box reads `source_message` / `source_line`, which SPEC-002 §4.2 drops. After the switch that box has no data and must be removed or hidden. The drop was confirmed on 2026-11-21; this is a reminder, not a change.
- The admin contract (`docs/api/admin/openapi.yaml`) still names `admin-api-staging.maemorkratai.com`; it is reviewed while planning SPEC-002b.
